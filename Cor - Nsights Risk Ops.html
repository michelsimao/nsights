Cor

Toda cor da interface vem de token. Este documento diz qual token usar em cada papel, como pintar estado em componente e o que o tema escuro exige.

Sete regras

  1. Nunca escreva hex numa regra de componente. Se a cor que você precisa não tem token, o passo é propor o token — não colar o hex.
  2. Estado se pinta com o par completo. Fundo e texto sempre da mesma família: --state-ok-bg com --state-ok-fg, nunca cruzado.
  3. Sólido é para marca, não para texto. -solid pinta bolinha, barra e preenchimento; texto sobre claro é sempre -fg.
  4. Chão saturado pede a tinta certa. Sobre --accent e -solid, use --on-accent; sobre a rampa escura, --on-dark. Nunca --text nem um escuro literal.
  5. Neutro tem matiz. O cinza do produto é roxo-acinzentado. Cinza puro (#8b8b9b e parentes de matiz 240°) não pertence à paleta.
  6. Um papel, um token. O mesmo estado nunca tem dois tons: "regular" é --state-ok-solid no badge e no ponto de gráfico; "sem dado" é o par --state-neutral-* em badge, pill e ponto, e --chart-neutral quando é série de gráfico.
  7. Cor nunca é o único indicador. Todo estado leva rótulo, ícone ou forma junto — gráficos incluídos.
Faça
.status-regular {
  background: var(--state-ok-bg);
  color: var(--state-ok-fg);
}
.status-regular > span {
  background: var(--state-ok-solid);
}
Não faça
.status-regular {
  background: #e6f5ee;
  color: #137a51;
}
.status-regular > span {
  background: #1f9a70;
}

3 · Estado em componentes

Cinco famílias, quatro papéis cada: -bg e -fg pintam badge, pill e alerta; -solid é bolinha, barra e preenchimento; -border é contorno de swatch e de faixa. Nenhuma família empresta token de outra — info tem o próprio --state-info-fg, mesmo coincidindo com o roxo da marca.

FamíliaQuando-bg + -fg-solid
okNada encontrado, fonte respondeu, conta ativa.#e9f5f0 · #176b4d#1f9a70
warnRessalva, dado defasado, agravante.#fff5e6 · #80540c#b0620d
dangerImpedimento, veto, falha de consulta.#fde9ee · #8f1833#b91c3c
neutralSem dado, em fila, cancelado, fora de escopo — tudo que ainda não produziu resultado.#eeeef2 · #4e4654#8d8491
infoAviso do sistema e veredito inconclusivo.#f4eefc · #5a159f#7024c7

--state-danger-strong (#8f0f2c) é exclusivo de veto: selo de veredito e borda esquerda do card. --state-danger-on-dark (#e0879a) é a única cor de estado permitida sobre superfície escura.

Progresso não é estado. "Em execução" usa a família da marca — --accent-soft com --accent-strong no pill, --accent no selo e na barra — porque indica atividade, não resultado. Só quando a consulta termina o elemento assume uma família de estado.

4 · Tema escuro

O escuro é troca de valor de token, nada mais: nenhuma regra de componente muda. Para que isso funcione, três exigências valem para todo componente novo.

  • Leia sempre --surface-raised para o fundo de card — nunca #fff. É esse token que vira #241d2a no escuro.
  • Não presuma tinta escura. Todo container define color: var(--text); o que herda de fora do container quebra quando o fundo inverte.
  • Sombra não substitui borda. Sobre superfície escura só a borda separa planos — use --border em vez de depender de box-shadow.

As ilhas escuras que já existem no produto claro (sidebar, rodapé do wizard, monogramas) usam a rampa própria: --dark, --dark-raised, --dark-border, --dark-border-strong, --dark-text, --dark-muted, --dark-accent. Não misture essa rampa com a de superfície: ela existe para o que é escuro por decisão de design, não por tema.
